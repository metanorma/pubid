= URN Patterns for All pubid Flavors

Version 1.0 (2026-08-19). Status: normative for implemented classes A/B; design
for class C.

This document defines the complete set of URN patterns produced by the pubid
reference implementation (`Identifier#to_urn`). The corpus in pubid-tests
records `representations.urn` exactly as the reference emits it, so this
document and the generators must stay in sync.

== Normative sources

1. `references/iso-urn-specification.adoc` — RFC 5141-bis (ISO URN).
2. `references/iec-urn-specification.adoc` — IEC URI Model.
3. Reference implementation: `lib/pubid/urn_generator/base.rb` (Base contract)
   and `lib/pubid/{flavor}/urn_generator.rb` (one subclass per flavor).

== Common rules (UrnGenerator::Base)

`Identifier#to_urn` resolves `Pubid::{Flavor}::UrnGenerator` and falls back to
`Pubid::UrnGenerator::Base` for flavors without a subclass (currently: doi,
gb, isbn, un).

Base segment order:

....
urn:{namespace}:{publisher}:{type}:{number}:{part}:{subpart}:{year}:{edition}:{language}
....

* Every segment is omitted when its value is absent (skip-if-nil), unless a
  flavor mandates the segment (e.g. `api` type, `tgpp` release/version).
* `part` and `subpart` render with a leading `-` (e.g. `-1`, `-2000`).
* `edition` renders as `ed.N`; languages render as comma-joined codes.
* Namespace identifiers are lowercase.

== Class A — formal SDO schemes

These flavors have published URN specifications; pubid implements them
verbatim (no internal variations).

=== ISO — RFC 5141-bis

Full grammar: see `iso-urn-specification.adoc`. Summary:

....
urn:iso:std:{originator}[:{type}]:{docnumber}[:{partnumber}]
  [:{status}][:{edition}][:{docversion}][:{language}]
  [:{suppltype}:{supplnumber}[:{supplversion}]]*
urn:iso:doc:{originator}:dir[:{edition}][:...]
....

* `originator` = publisher-copublisher with hyphens (`iso`, `iso-iec`,
  `iso-iec-ieee`).
* `type` ∈ data/guide/isp/iwa/pas/r/tr/ts/tta (std); dir/dir-sup (doc).
* `partnumber` keeps its leading dash (`-1`).
* **Year never appears** — edition (`ed-2`) replaces it.
* Supplements chain recursively: `:amd:1:v3:cor:1:v1`.

Examples (verified output):

----
"ISO 9001"                → urn:iso:std:iso:9001
"ISO/IEC 9999-1:2022"     → urn:iso:std:iso-iec:9999:-1
"ISO 9001:2015/Amd 1:2020"→ urn:iso:std:iso:9001:amd:2020:v1   (supplement form)
----

=== IEC — URI Model

Full grammar: see `iec-urn-specification.adoc`. Summary:

....
urn:iec:std:{header}:{docnumber}[:{date}][:{type}][:{deliverable}]
  [:{language}][:[:{adjunct-type}:{adjunct-number}[:{adjunct-date}]]*]
....

* Part is **inside** `docnumber` (`60601-1-1`), unlike ISO.
* `date` = year[-month[-day]]; **year appears in the URN**, unlike ISO.
* Adjunct relation markers: `::` reference, `:plus:` consolidation.
* Empty positional segments are preserved as `:` (trailing colons are
  significant positional markers):

----
"IEC 60601-1-1:2005" → urn:iec:std:iec:60601-1-1:2005:::
----

=== IALA — MRN (not URN)

....
urn:mrn:iala:pub:{code}[:ed{edition}][:language]
urn:mrn:iala:pub:{code}:{annex-segment}[:ed{edition}][:language]
....

== Class C — `urn:pubid:identifier:` universal namespace (design)

Formal schemes exist only for ISO/IEC (class A) and per-flavor namespaces are
not registered URN namespaces (class B). The internal universal namespace
gives every flavor a syntactically valid, round-trippable identifier URN, for
pubid/pubid-ts interchange.

....
urn:pubid:identifier:{flavor}:{component}[:{component}...]
....

* `pubid` — namespace identifier (NID).
* `identifier` — resource-class discriminator: `identifier` for document
  identifiers, `publisher` for publisher records, `type` for type schemas.
* `{flavor}` — lowercase registry key (`iso`, `iec`, `3gpp`, ...). Applies to
  ALL flavors, including those with formal schemes.
* `{component}` — the flavor's own canonical component names and values
  (exactly the keys recorded in the corpus `identifier` mapping), lowercased
  where the value is a symbolic component (publisher, type, language).

Examples:

----
urn:pubid:identifier:ansi:ANSI:C37.16:2000
urn:pubid:identifier:iso:iso-iec:tr:9999:1:2022
urn:pubid:identifier:oiml:r:52-1:2017:e
----

Encoding rules: percent-encode space, `/`, `:` inside values; every component
key is implicit by position (fixed per-flavor order documented in the corpus
schema). Implementation is tracked in `TODO.restructure/27-ts-urn.md` and
`TODO.restructure/15-urn-declarative.md`.

== Known defects (recorded as-is in the corpus)

The corpus records `representations.urn` verbatim from the reference
implementation. Defects are governed by `tests/{flavor}/_status.yaml` (DIRTY
ledger), never silently corrected here:

* **Illegal characters (RFC 8141 pchar)** — spaces: `urn:etsi:ets:300 011:...`,
  `urn:jis:A 0001:1999`, `urn:cie:bundle.CIE 198-SP1.1:2011,...`; reserved
  `/`: `urn:itu:t:I.363:1993:1:11/1993`, `urn:asme:api/asme:...`,
  `urn:ashrae:...copub.ansi/ashrae`.
* **Ruby object-inspect leak**: `urn:amca:204:copub.amca:{key:
  :interpretation, title: "interpretation", short: "interp"}` — a component
  renders via `to_s` on a raw Ruby structure instead of its URN form.
* **Value-dropping (bare or truncated namespace)**: `urn:doi`, `urn:isbn`,
  `urn:omg`, `urn:bsi:bs`, `urn:astm:std`, `urn:ieee:ire`, `urn:un:1`,
  `urn:ashrae:140` — the generator emits the namespace while dropping the
  distinguishing components.
* **Lossy parses**: `ANSI C37.16-2000` mis-segments year into part
  (`urn:ansi:C37.16:-2000`); `ASTM A36/A36M-14` collapses the designation.
* **Quirk (retained by design)**: nist renders a nil supplement as `supp`
  (`urn:nist:circ:1.supp`); IEC preserves empty positional segments
  (`...:2007:::::amd:1:2009`).

CLEAN means the reference is self-consistent (parse → render/URN
regeneration matches the recorded corpus), **not** that the URN is
RFC 8141-valid; validity gaps above are per-flavor ledger items.

== Corpus recording contract

* `representations.urn` is present iff the reference `to_urn` returned a
  non-nil string for the canonical re-parse of `representations.human`.
* The exporter's verify gate re-parses and asserts `id.to_urn == urn`
  (generation determinism), and the conformance runner's `urn` gate repeats
  the assertion for any implementation claiming conformance.
