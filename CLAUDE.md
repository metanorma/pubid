# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

PubID is a Ruby gem for creating interoperable identifiers for standards documents (ISO, IEC, NIST, IEEE, etc.). The codebase lives in a single gem with all flavors under `lib/pubid/{flavor}/`. There are 22+ supported flavors.

## Common Commands

```bash
# Install dependencies
bundle install

# Run all tests
bundle exec rake test:all

# Run integration tests (cross-flavor)
bundle exec rake test:integration

# Run the default suite (test:all + test:integration)
bundle exec rake

# Lint all code
bundle exec rake rubocop        # rubocop:all is an alias

# Build the gem (into pkg/)
bundle exec rake build

# Version management (version lives in lib/pubid/version.rb)
bundle exec rake version:show                     # Show gem version
bundle exec rake version:bump[patch|minor|major]  # Bump version

# Validation (per-flavor parser accuracy)
bundle exec rake validation:report             # Summary for all flavors
bundle exec rake validation:classify[iso]      # Classify one flavor's results
bundle exec rake validation:classify_all       # Classify all flavors
```

For running specific test files during development, use rspec directly:

```bash
bundle exec rspec spec/pubid/iec/identifiers/technical_report_spec.rb
bundle exec rspec spec/pubid/iso/              # all ISO tests
```

## Architecture

### Parse Pipeline

```
Input String
    │
    ▼
Pre-parser Normalization (data/{flavor}/update_codes.yaml)
    │
    ▼
Parser (Parslet PEG grammar → parse tree)
    │
    ▼
Builder (parse tree → attribute hash)
    │
    ▼
Identifier (Lutaml::Model object → to_s / to_urn / to_h)
```

### Flavor Module Structure

Each flavor under `lib/pubid/{flavor}/` follows:

```
lib/pubid/{flavor}/
├── parser.rb          # Parslet PEG grammar
├── transformer.rb     # AST → attribute hash (some flavors)
├── builder.rb         # Parse tree → identifier object
├── scheme.rb          # Identifier type registry (some flavors)
├── identifier.rb      # Top-level entry point (parse method)
├── identifiers/       # Type-specific classes (e.g., international_standard.rb)
├── renderer/          # Output formatting (some flavors)
├── urn_generator.rb   # URN output (most flavors)
└── urn_parser.rb      # URN input (ISO, IEC)
```

### Flavor notes

Each flavor's own forensics live in `lib/pubid/<flavor>/CLAUDE.md`, next to that
flavor's code. Claude Code auto-loads a directory's `CLAUDE.md` when you work
with files in it, so a flavor's forensics load automatically — no index to
keep in step, and no manual "read this first" step (relaton, the sibling gem,
uses this same layout). **Add to that file — not to this one — when you
finish a flavor branch.** The bullets after this section are the cross-flavor
contract, which every flavor obeys.

These files are not the same as `docs/identifier-patterns/<flavor>.md`, which
`rake docs:patterns` generates from the code.

### Key Patterns

- **Parslet PEG parsers**: Each flavor defines grammar rules in `parser.rb`
- **TypedStage**: `Pubid::Components::TypedStage` with attributes: name, type_code, stage_code, abbr, harmonized_stages. Defined as `TYPED_STAGES` arrays on identifier classes.
- **Scheme class**: Some flavors (IEC, ISO) use a `Scheme` class as a registry for identifier types and typed stages
- **Lutaml::Model**: Serialization framework for identifier objects (`to_h`, `to_json`, custom mappings)
- **Canonical `to_hash` (no defaults)**: `Pubid::Identifier#to_hash` drops any attribute whose value is empty or equal to its default, so the serialized hash is a pure function of the identifier's values — `parse(s).to_hash`, `from_hash(h).to_hash`, and a manually-built id all agree, and the round-trip is idempotent (`from_hash(x.to_hash).to_hash == x.to_hash`). relaton-index relies on this exact equality to validate stored rows. The canonicalizer **recurses into nested components/identifiers** (`canonicalize_hash`/`canonicalize_nested`), because lutaml serializes a nested `Components::*` via its own transform — not the component's public `to_hash` — so a nested defaulted attribute (e.g. `Components::Supplement#has_revision`, default `false`) would otherwise leak into the parent hash. This works because pubid never consults lutaml's `using_default?` tracking and defines no `render_default: true` mapping; **do not** add a `render_default: true` mapping (it would need a default-valued attribute serialized, which `to_hash` now strips) without revisiting this invariant.
- **Compact flavor `key_value` mappings (ISO/JCGM/OIML/ETSI/ITU)**: flavors that want a flat, index-friendly hash declare a `key_value do … end` block that collapses `Components::*` to bare scalars — e.g. ETSI serializes a top-level `number` (plus a `parts` array, omitted when empty), `Version` as a scalar `version` + an `is_edition` boolean (omitted when false), and `Date` as top-level `year`/`month`/`day`. **Note for ETSI and OIML the flat keys are now real attributes, not converters reading through a `code` component** — see the ETSI/OIML index-key bullet below; the emitted hash is unchanged, but `map "number", to: :number` replaced `number_to_kv`/`number_from_kv`. The constant `publisher` ("ETSI") is intentionally **unmapped** and reconstructed from its attribute default, so it never bloats a row. **Placement matters when a flavor has a supplement/wrapper subtype that *delegates* attributes to an inner id**: ETSI's `SupplementIdentifier` (Amendment/Corrigendum) delegates `type`/`code`/`version`/`date` to its `base`, so the standard block lives on the **leaf `EtsiStandard`**, not the shared `Identifier`/`Base` — a block on the shared parent would be inherited-and-merged by the supplement and re-emit every delegated field at the top level (the old redundant shape). The supplement declares its own minimal block (`_type` + ordinal `number` + nested `base`), reconstructing `base` via `Pubid::Etsi::Identifier.from_hash` (a bare polymorphic cast would rebuild a plain `Base` and lose the concrete subclass). The per-flavor helpers (`emit_kv`, `date_for`, `year_to_kv`/…) are currently duplicated across jcgm/oiml/etsi by convention — mirror an existing flavor when adding another. **ITU** follows the ETSI pattern: the shared converter helpers live once on `Pubid::Itu::Identifier` (`identifiers/base.rb`), and the leaf standard block is installed via the `Identifiers::StandardSerialization` mixin (an `included` hook — lutaml **merges** a mixin-installed block with a second in-class `key_value` block, so `Question` adds `study_group`/`has_bl`/`bracketed`/`has_colon` and `CombinedIdentifier` adds `combined` on top). Leaf placement is load-bearing here too: `Supplement` (parent of `Amendment`/`Corrigendum`/`Errata`) and `Annex` declare their **own** minimal blocks with a nested-but-flat `base` via `Pubid::Itu::Identifier.from_hash`; a shared-parent block would make them re-emit `base`'s fields. **ITU supplement edge case:** the supplement copies `sector`/`series` from its base, so its block emits them **only when `base` is nil** (the series-only `ITU-T H Suppl. 1` form) via `supplement_sector_to_kv`/`supplement_series_to_kv` (guard `model.base.nil?`) — otherwise they duplicate the base. **A block on a flavor's own `Identifier` REPLACES the base maps of `::Pubid::Identifier`, it does not extend them**, so every attribute the flavor uses must be listed: `Pubid::Gb::Identifier` omitted `date` and therefore dropped the publication year from `to_hash` for **every** dated GB identifier, while `to_s`, `year` and `exclude` stayed correct — the silent `#matches?` inequality again, plus two editions of one document collapsing onto one hash. The one-line `map "date", to: :date` is enough, because the shared flat-scalar rules then emit a bare `"year"`. GB publishes no index, so no re-crawl follows. GB also shows the **other** half of the same audit: it declared its own `publisher_code` string while the `publisher` it inherits stayed nil, so two attributes described one value and every shared surface that reads `publisher` saw nothing — the URN dropped the series and `GB 20223-2006` collided with `GBn 20223-2006`. Reusing the inherited component (plus a per-class `flat_scalar_components`/`flat_scalar_fields` entry, the CEN precedent, so it still serializes as a bare scalar) repaired the URN, the MR slug and annotated rendering at once. **Prefer the inherited attribute over a parallel one**; a flavor-named duplicate is invisible to shared code (`lib/pubid/gb/CLAUDE.md`).
- **`exclude` recurses into nested identifiers**: `Pubid::Identifier#exclude(*attrs)` (and the `:year`→`:date` alias) nils the named attributes and rebuilds via **`self.class.new(**attrs)`** (a keyword splat — issue #289). **The `:year` alias is additive, not a substitution** — `exclude(:year)` keeps `:year` in the exclusion set **and** adds `:date` (`excluded_args << :date if excluded_args.include?(:year)`, *not* `.delete`), so the attribute loop nils **whichever name the flavor actually declares**: `date` for a year-in-`Components::Date` flavor (ISO/ITU/…), a plain `year` attribute for a lone-scalar-year flavor (GOST/astm/asme/api/ogc/easc/jis). This means a flavor whose edition is a **lone `year` scalar with no format siblings needs no `#exclude` override at all** — the base handles it (GOST issue: `exclude(:year)` was a silent no-op before this, because the old `.delete(:year)` dropped `:year` and mapped only to the non-existent `date`). The mapping is one-directional (only `:year` adds `:date`; `exclude(:date)` never adds `:year`), so a plain `year` always survives a date-only exclusion. The `**attrs` keyword splat is what makes the rebuild work for every flavor whether its identifier `initialize` is positional (the base `initialize(attrs = {}, options = {})`) or **keyword-only** (ITU `**kwargs`, IEEE `**args`, NIST `**attributes`). Under Ruby 3 kwarg separation the earlier positional `self.class.new(attrs)` raised `ArgumentError` for every keyword-init flavor, breaking `#matches?` (which calls `exclude`) — so **do not** revert this to the positional form. (One laggard remains: AMCA `Publication`/`Interpretation` use a *named*-keyword `initialize` with non-attribute ctor params, so the attribute-hash rebuild can't reconstruct them — they still need their own `exclude` override.) Any attribute value that *is* (or is a collection of) another `Pubid::Identifier` is passed through `exclude_from_nested`, which re-applies the same exclusion to the inner identifier. This is what makes `exclude(:date)` actually drop the publication date on wrapper types (BSI `AdoptedEuropeanNorm`/`ConsolidatedIdentifier`/`ExpertCommentary`, and any flavor that delegates `date` to an inner id) instead of nilling an unused outer attribute. Components and scalars are copied verbatim — only real `Identifier` instances recurse — so flat identifiers (ISO, IEC …) are unaffected. **ETSI and ITU override `exclude_from_nested`** to reach a part stored *inside* a Code component: both keep number+part in one `Components::Code`, so excluding `:part`/`:parts` returns a Code copy with `parts: []` (keeping the number/series), letting a part-less reference match every edition via `matches?(other, ignore: [:parts])` (ITU editions `P.838` ↔ `P.838-3`). **BIPM also overrides `exclude`** to re-nil its own `year` integer attribute after `super` — redundant but harmless now that the base nils a declared `year` directly; kept to avoid churn. A partial BIPM ref is a year wildcard under `matches?(row, ignore: [:year])`. **CSA follows the same scalar-year pattern**, but its year carries format-metadata siblings that the override must reset too — `lib/pubid/csa/CLAUDE.md`. **Lesson for any future scalar-year flavor**: the base already nils a lone `year` scalar, so an `#exclude` override is needed **only** when the year has sibling/format attributes (CSA's `year_format`/`year_prefix`/`original_year_4digit`/`french`) or a differently-named scalar cluster (IEEE's `year`/`month`/`day`) that the base can't reach — and then it must reset the *whole* cluster, not just the year scalar. A lone `year` with no siblings (GOST/astm/asme/api/ogc/easc/jis) needs no override. **A supplement (Amendment/Corrigendum) owns a date of its own, nested one level inside a wrapper that owns none**, so the unlimited recursion above — right for a wrapper, whose own date is nil — is wrong for a supplement: a bare `exclude(:date)`/`exclude(:year)` on a consolidated identifier should drop only the base standard's date, not the attached amendment's. `self.class.supplement_date_attributes` (default `[]`, a no-op for every flavor that doesn't override it) names the attributes on *this* class that hold that own date; `#exclude` protects them from a bare `:date`/`:year` and clears them instead on the explicit key `:supplement_year`. CEN/CENELEC and BSI `Amendment`/`Corrigendum` declare it. Detail: `lib/pubid/bsi/CLAUDE.md`'s "The `exclude` recursion boundary" (hand-off: `metanorma__pubid__exclude-recursion-depth`).
- **Uniform parent accessor (`base`) and `#root`**: a wrapper/supplement identifier exposes the document it wraps under a single attribute named **`base`** (polymorphic `Pubid::Identifier`). This name is uniform across *every* flavor — the earlier split where some flavors used `base_identifier` and others `base` was collapsed by renaming `base_identifier` → `base` everywhere (Ruby attribute/method **and** the on-disk serialization key). `#root` (`lib/pubid/identifier.rb`) walks `base` recursively to the origin document: `base ? base.root : self`; a plain standard (`base` nil) is its own root. **Wrappers that store members in an `identifiers` collection instead of `base`** — `ConsolidatedIdentifier` (iec/bsi/cen_cenelec) — override `#root` to walk `identifiers.first.root`. **CSA's container types** (`WrapperIdentifier`/`CompositeIdentifier`/`Bundled`/`Combined`) used to descend from `Lutaml::Model::Serializable` and define `def root; self; end`; they are now real `Pubid::Csa::Identifier` subclasses carrying a polymorphic `base` (see the CSA bullet in `lib/pubid/csa/CLAUDE.md`), so the first three inherit `#root` and only `Combined` overrides it, walking its `identifiers` collection. The registry-driven `spec/pubid/root_spec.rb` locks this. **relaton note**: relaton-* consumed the old `.base_identifier`; they must migrate to `.base` (no alias is kept), and flavors whose on-disk key changed from `base_identifier` → `base` (cen_cenelec, cie, nist, idf, ieee, bsi, plateau, ashrae, iala, oiml) need their `relaton-data-*` indexes regenerated. **Index-key corollary — every leaf must have a non-empty `number`**: relaton-index keys its binary-search narrowing on `root.number` (a wrapper files under its origin standard's number; a leaf is its own root). So **every** identifier that can be a `root` must expose a non-empty `number`, including non-`Standard` leaves — CIE proceedings papers store the paper string as `number` (`"OP02"`; the x-form's conference is a separate `conference_number`), and CIE `TutorialBundle` mirrors its ordinal into `number`. A comma-list `Bundle` instead models its members as `ids` (a polymorphic `Identifier` collection, mirroring IEC's `ConsolidatedIdentifier`); since a CIE bundle is the parts of one supplement of one standard, the shared `base` is hoisted to the bundle (each id keeps only its differing supplement `number`/`part`) and `#root` walks that `base` — so it keys via the members' origin standard and needs no stored `number`. (The builder falls back to per-id bases if members ever don't share one; not seen in practice.) A leaf with a nil `number` yields the empty key `""` and silently defeats the binary search. `spec/pubid/cie/index_number_spec.rb` locks `root.number` non-empty for every CIE type.
  **Not every wrapper names its parent `base` yet** (CEN and IEEE adoptions do not), and a wrapper's hand-written `#number` delegation hides a missing `#root` from the index key — the survey is in `lib/pubid/bsi/CLAUDE.md`.
- **Uniform per-flavor handle (`Pubid::<Flavor>::Identifier`, not `Identifiers::Base`)**: every flavor's canonical, public handle is the class **`Pubid::<Flavor>::Identifier`** — a real `::Pubid::Identifier` subclass that is the common ancestor of *all* that flavor's concrete types (including wrapper/supplement subtypes) and the host of the shared polymorphic `from_hash`. It is the class to pass anywhere a flavor's identifier class is needed (e.g. relaton-index's `pubid_class:`); `Pubid::<Flavor>::Identifier.from_hash(h)` dispatches to the right concrete subtype by `_type` regardless of receiver. The legacy `Pubid::<Flavor>::Identifiers::Base` name survives **only** where it is still a genuine *intermediate* class carrying shared "single-document" attributes that wrapper subtypes deliberately bypass — **Category B: `iec, asme, api, astm, csa, ccsds, cen_cenelec`** (there `Base < SingleIdentifier`/`< Identifier`, an internal implementation class, *never* the public handle: it is narrower than `Identifier`, excluding wrappers). Every other flavor (**Category A**) used to define `Identifiers::Base = Identifier` as a pure alias; that alias is now **removed** — `Identifiers::Base` is undefined there and code must use `Identifier`. Two cross-flavor specs lock this: `spec/pubid/identifier_hierarchy_spec.rb` (Category-A `Identifiers::Base` undefined, Category-B present-and-distinct) and `spec/pubid/uniform_identifier_handle_spec.rb` (`from_hash(x.to_hash).to_hash == x.to_hash` through the `Identifier` handle for every flavor, wrappers included). **Landmine**: bare `Base` inside a flavor can mean an *unrelated* nested class — `Pubid::Nist::Series::Base` (`nist/series/*`) and `Pubid::Ieee::Identifiers::Nesc::Base` (`ieee/identifiers/nesc/*`) — so never blanket-rename `Base`. **relaton note**: consumers passing a Category-A `Pubid::<Flavor>::Identifiers::Base` (e.g. IHO crawler `pubid_class:`) must migrate to `Pubid::<Flavor>::Identifier`; NIST/IEC crawlers already do.
- **Matching primitives (`base_document` / structural `exclude` / `matches?`)**: `Pubid::Identifier` exposes the vocabulary relaton uses to match a reference against catalogue hits without regexes. `#base_document` returns the wrapped standard with amendment / corrigendum / Expert-commentary / Flex-version layers peeled recursively (base case returns `self`; wrappers override it, delegating to `base`/`identifiers.first`). `#exclude` also accepts the **structural** keys `:amendment`/`:supplement` (reduce one supplement layer via `#drop_supplements`, which `ConsolidatedIdentifier`→`identifiers.first` and `Amendment`/`Corrigendum`→`base` override) alongside attribute keys like `:date`/`:edition`. `#matches?(other, ignore:)` is just `exclude(*ignore) == other.exclude(*ignore)` **on the base class** — NIST overrides it as an asymmetric wildcard query (`matches?(candidate)`, no `ignore:`), so generic predicates must compare `exclude(…)` directly. The **relational algebra** (`pubid#247`) lives on the same class: `supplement_of?`, `has_supplement?`, `dated_version_of?`, `revision_of?`, `sibling_of?`, `includes?`, `draft_of?`, `edition_of?`, and the `related_to?` disjunction. `revision_of?` reads `REVISION_ATTRIBUTES` (`revision`, `update`, `update_component`) through the public `revision_marker` — OGC/IEEE carry a string, NIST an `Update` component; a revision modelled as an edition belongs to `edition_of?`. BSI and CEN `Amendment`/`Corrigendum` expose `supplement_type` (`:amendment`/`:corrigendum`) and plain `:string` `number`/`year`, so callers never special-case corrigenda; the `supplement_number`/`supplement_year` aliases were deleted, and the CEN exclude key `:supplement_year` is unaffected (`lib/pubid/bsi/CLAUDE.md`).
- **Subset match (`reference === candidate`)**: every component class must `include ::Pubid::SubsetMatch`. Read `docs/SUBSET_MATCH.md` first — it carries `subset_strict` (a nil value means "none") and the `all_parts` wildcard.- **Flavor prefix routing (`Pubid::<Flavor>.prefixes`)**: every registered flavor exposes a uniform, static `prefixes` class method returning `Array<String>` of the **leading identifier prefix tokens** it recognizes (the tokens a printed id can start with), used by relaton to route a reference string to the owning SDO. A flavor gets this by `extend Pubid::PrefixesSupport` (`lib/pubid/prefixes_support.rb`) and defining a frozen `PREFIXES` constant holding **only its own** tokens, sourced from the parser grammar/constants (e.g. IEC derives from `Components::Publisher::PUBLISHERS.keys`). Joint/co-publication tokens (`ISO/IEC`, `ISO/IEC/IEEE`, `ANSI/ASHRAE`…) live **only** in the central `Pubid::JOINT_PREFIXES` map in `lib/pubid.rb` and are merged in by the mixin, so a co-published prefix appears **symmetrically** in every co-publisher's list without hand-duplication. Top-level helpers: `Pubid.prefixes(:iso)` and `Pubid.prefix_flavors` (reverse index `{ "ISO/IEC" => [:iec, :iso], … }`, which de-dups the `:cen`/`:cen_cenelec` alias by module identity). **Inclusion policy** (documented in the mixin's YARD): include publisher prefixes and leading series/type tokens that can *begin* a reference (BSI `DD`/`PD`, NIST `FIPS`); **exclude** pure sub-series that never lead a reference and ambiguous single letters (BSI aerospace `A`/`B`/`C`). When adding a new flavor, `extend Pubid::PrefixesSupport` and define `PREFIXES` (the cross-flavor spec `spec/pubid/prefixes_spec.rb` asserts every registered flavor responds).
- **A component-typed attribute must default to a component, never to a raw scalar**: `to_hash` drops a default-valued attribute, so `from_hash` finds no key and casts the *default* into the component — and a Symbol or String default raises `Lutaml::Model::InvalidFormatError` there. `to_s`, `to_urn` and `to_hash` all stay correct, so only a deserialization sees it (pubid#383: every EVS and IDF `from_hash` raised on `default: -> { self.class.type[:key] }`, and **all 10** EVS corpus cases raised, not the single row the testsuite ledger named — the exporter looked clean because `Conformance::Generator#round_trips?` rescues `StandardError`). The shape to copy is cen_cenelec's: a `self.class.default_type` class method returning `Components::Type.new(abbr: type[:short])`. **Do not read `self.class` inside the default lambda body itself** — lutaml calls the lambda plainly (`options[:default].call`) when it has no instance, and `self.class` is then `Class`; going through a class method keeps that resolution in one place. Two specs lock it, and they are complementary: `spec/pubid/evs/from_hash_spec.rb` greps `lib/` for the one raw spelling, while `spec/pubid/component_attribute_default_spec.rb` **evaluates** every component-typed default of every identifier class of every flavor, so a raw default of any spelling or component type fails, and an attribute whose type or default cannot be resolved is reported rather than skipped. Detail in `lib/pubid/evs/CLAUDE.md`.
- **A `collection: true` attribute needs `initialize_empty: true`, or the two construction paths disagree**: `Pubid::Tgpp::Identifier#parts` was declared `collection: true` with no default. `Builder#build` always passes `parts: extract_part_strings(…)`, which returns `[]` when the grammar matched no part, so a **parsed** part-less identifier held `[]`; the serialized hash carries no `parts` key at all, so `from_hash` never set the attribute and a **deserialized** one held `nil`. The two were therefore not `==`. **Why that is a silent, high-blast-radius bug rather than a cosmetic one**: `#matches?` is `exclude(*ignore) == other.exclude(*ignore)` and `#exclude` rebuilds through `self.class.new(**attrs)`, so the `[]`/`nil` difference survives the exclusion and every *matching* call fails too — and it fails by returning `false`, so a relaton index lookup (parsed user reference vs `from_hash`-ed index row) just returns nil with no error. Measured on `relaton/relaton@feat/3gpp-consume-index-v2`: **366 of 387** fixture rows failed to match — precisely the part-less ones, while the 21 parts-carrying rows matched because both sides then held `["04", "1"]`. The fix is `attribute :parts, :string, collection: true, initialize_empty: true` (`lib/pubid/tgpp/identifier.rb`). **`initialize_empty: true` is the preferred spelling for this from now on**, and it is not a second mechanism: lutaml's `Attribute#set_default_for_collection` desugars it to `@options[:default] ||= -> { build_collection }`, i.e. *exactly* the `default: -> { [] }` that `Ieee::Identifiers::CodeNumber` / `IecIeeeCopublished` / `Itu::CombinedIdentifier` already use (verified identical on `default_set?`, `default`, `to_hash`, `==`, and per-instance array identity). Two reasons to prefer it: it names the intent rather than restating the mechanism, and lutaml **raises** if it is given without `collection: true` (`validate_options!`), so a later edit that drops `collection: true` fails loudly instead of silently defaulting a scalar attribute to `[]` — a failure mode a bare `default: -> { [] }` cannot catch. The 10 existing `default: -> { [] }` / `default: []` collection declarations are left alone; this is guidance for new ones, not a migration. **The default does NOT put the key back into the hash, and the mechanism is worth getting right** because the obvious explanation is the wrong one: it is **lutaml's key_value serializer that omits an empty collection**, on its own, whether or not a default is declared — *not* pubid's `canonicalize_hash`. Before the default existed, `default_set?` was `false`, which short-circuits `default_valued?` (`lib/pubid/identifier.rb`) to `false`, so the canonicalizer demonstrably could not have been what dropped the key; the raw lutaml serialization already had no `parts` (verified both ways with `Pubid::Identifier.instance_method(:to_hash).super_method`). The consequence is the useful part: **the serialized shape is byte-identical before and after**, and only what `from_hash` leaves in the attribute changes. So all four checks hold at once: `from_hash(…).parts == []`, `parse(s) == from_hash(parse(s).to_hash)`, and `to_hash` still omits `parts` for the ~81,000 part-less rows of the 88,464-row published index. That last point is why the fix belongs on the **attribute**, not on `to_hash`: emitting `parts: []` would inflate the artifact and be an index-format change forcing a re-crawl. Nothing stored changes, so **no index migration follows**. **The spec lesson generalises past 3GPP**: `serialization_spec.rb` already round-tripped all 11 refs and never caught this, because it compared `to_s` and `to_hash` — both of which were *already correct* (rendering ignores an empty collection, and the hash omits it on both sides). Only `==` sees it. A flavor's round-trip spec must assert `from_hash(id.to_hash) == id`, not just that the two render or serialize alike. **The other flavor with this exact declaration solved it the other way, and is deliberately left alone**: `Pubid::Jis::Identifier#parts` (`lib/pubid/jis/identifier.rb`) is also `collection: true` with no default and shows the identical `[]`/`nil` asymmetry, but JIS hand-writes its `==` (`identifier.rb:96`) and normalises there — `(parts || []) == (other.parts || [])` — so it has no observable defect. Two remedies, then: normalise in `==`, or default the attribute. Prefer the **default**, because it is one line, it fixes every consumer of the attribute rather than only the comparison, and it needs no bespoke `==` to maintain — but the upshot for auditing is that a `collection: true` attribute with no default is only a *suspect*, not a defect: **check `==` before assuming another one is affected.** (hand-off: tgpp-parts-collection-default; consumer follow-up: `relaton/relaton` branch `feat/3gpp-consume-index-v2` can drop its `Bibliography#pubid_match?` workaround — which compares `exclude(*ignore).to_hash`, immune because `to_hash` omits `[]` and `nil` alike — for a plain `pubid.matches?(row_id, ignore:)`.)
- **One error namespace (`Pubid::Errors`), unified by a marker module**: every failure pubid raises includes the module **`Pubid::Errors::Error`**, so `rescue Pubid::Errors::Error` is exhaustive. There are three classes, and **their superclasses are the backward-compatibility contract, not an accident**: `Pubid::Errors::ParseError < ::Parslet::ParseFailed` (a printed identifier), `Pubid::Errors::UrnParseError < ::StandardError` (a URN), `Pubid::Errors::InvalidInputError < ::ArgumentError` (non-String or over-long). - **Input-length guard (ReDoS)**: every public `parse` entry point (`Pubid.parse`, `Pubid::{Flavor}.parse`, and the class-level `{Flavor}::Identifier.parse` / `Parser.parse` funnels) rejects strings longer than `Pubid::MAX_INPUT_LENGTH` (1000) with `ArgumentError` **before** they reach the normalization regexes. It is true now, and `spec/pubid/parse_error_spec.rb` asserts it per flavor rather than leaving it to prose. Two variants were their own bugs: **ISBN had the guard but swallowed it** — a method-level `rescue ArgumentError` (there to turn the Builder's check-digit failure into a parse error) caught the guard's own `ArgumentError` and re-raised it as a `RuntimeError`, so the fix was to move the parse into a private `build_identifier` and leave both guards outside that rescue; and **ITU had `MAX_INPUT_LENGTH` only as an early *return*** inside `normalize_whitespace`, never a raise, under a comment asserting "`Pubid.parse` rejects it before this point" — which was wrong twice over, since `Pubid.parse` did not route a human-readable string to a flavor at all (`lib/pubid.rb` raised `ArgumentError: No flavor specified`; it now routes by prefix — see the prefix-routing bullet below). **The `nil` half of the guard is new**: reaching `.length` on nil produced a `NoMethodError` in 35 flavors, so the type check goes *immediately above* the length check, sharing its inline style.
- **Uniform `Identifier.parse` interface**: every registered flavor exposes **both** a module-level `Pubid::{Flavor}.parse(string)` **and** a class-level `Pubid::{Flavor}::Identifier.parse(string)`, each taking one required positional string and returning a `Pubid::{Flavor}::Identifier` (ISO is a compatible superset: `parse(string, format: :auto)`, still one required positional). The base `Pubid::Identifier` defines **no** `parse`, so each flavor must supply its own. Most flavors define the real logic on `Identifier.parse`; flavors whose logic lives in the module method (jcgm, nist, plateau, oiml) make the class method a one-line delegation `def self.parse(x); Pubid::{Flavor}.parse(x); end`, and keep the ReDoS length guard on the module method. When adding a new flavor, ensure `{Flavor}::Identifier` responds to `.parse` — the cross-flavor spec `spec/pubid/parse_interface_spec.rb` (registry-driven, like `prefixes_spec.rb`) asserts this for every registered flavor.
- **Partial reference parsing (optional date/version/year)**: every flavor's `parse` must accept a **partial** reference that omits the trailing publication date / version / edition — e.g. `ISO 9001` (no year), `ETSI EN 300 175` (no version/date), `CCTF REC 2` (no `(YYYY)`) — leaving the omitted attribute **`nil`** (never a default). This is what lets relaton look a document up by a bare reference and match a whole collection (all editions/dates/parts) via the matching primitives (`#matches?(other, ignore:)` = `exclude(*ignore) == other.exclude(*ignore)`); a partial ref only works if it *parses* with the omitted component nil so `exclude`/`matches?` treat it as a wildcard. Most flavors already satisfy this (ISO/IEC/NIST/IEEE/ITU/GOST/BSI/CEN/ETSI…); the **reference implementation** is ETSI — `lib/pubid/etsi/{parser,builder,renderer}.rb` — establishing the uniform three-step pattern: (1) **parser** makes the trailing date/version suffix `.maybe`, each `.maybe` guarding its own leading separator so no trailing separator is demanded (mandatory core stays `publisher + number`, mirroring ISO); (2) **builder** returns `nil` for the absent component instead of building an empty/defaulted one (so the canonical no-defaults `to_hash` drops it); (3) **renderer/urn_generator** append the date/version only when present, so a full id renders byte-identically and a partial renders without a stray separator. The invariant is enforced by the registry-driven cross-flavor spec `spec/pubid/partial_ref_spec.rb` (like `prefixes_spec.rb`/`parse_interface_spec.rb`): a `PARTIAL_REFS` table keyed by the registry's lowercased string flavor name (so `"cen"`, `"cen_cenelec"` and `"3gpp"` all appear) maps each flavor to `{ ref:, omits: }`, two meta-tests assert **every** registered flavor has an entry (and no stale entry) — the forcing function for new flavors — and a per-flavor example parses `ref` and asserts each `omits` attribute is `nil`. **`omits` categories:** (a) flavors with a separable trailing component assert it nil — most use `:year` or `:date`, ETSI uses `%i[version date]`, and note **W3C** (`omits: [:date]`, e.g. `W3C NOTE-xml-names`) and **OASIS** (`omits: [:version]`, e.g. `OASIS EDXL`) *do* carry an optional separable date/version despite otherwise reading like whole-identity ids; (b) truly no-date flavors whose natural form is the whole identity (IANA/XSF/IETF/OGC/PLATEAU/adobe/ecma/ccsds/iala…) use `omits: []`, a plain "still parses" guard; (c) **AMCA currently *requires* the trailing `-YY` year**, so no partial form parses yet — it uses `omits: []` with the canonical **full** ref as a parse-only guard, and adding real partial-ref support for it is outstanding laggard work (it is now the only such laggard). When adding a new flavor, keep the trailing date/version optional and add its `partial_ref_spec.rb` entry. **Registry-enumeration prerequisite:** this spec (and `prefixes_spec`/`parse_interface_spec`) only cover a flavor if `Pubid::Registry.flavor_names` includes it, which requires `eager_load_flavors!` to load its module — its constant filter is `/\A[A-Z][a-zA-Z0-9]+\z/` (**the `0-9` matters**: without it the digit-bearing `W3c` module is silently dropped from the registry, from every registry-driven cross-flavor spec, **and** from `Pubid.parse` prefix auto-routing). Two per-flavor gotchas the pattern surfaces: **fail-corpus migration** (a bare form previously listed in `spec/fixtures/{flavor}/…/fail/` must move to `pass/` once it parses — otherwise the "rejects every fail fixture" spec breaks), and **wrapper forms** where the date lives on an inner identifier (adoption/consolidated/amendment) may need the optionality applied there too. A further gotcha discovered across bipm/cie/csa/ashrae: when a flavor stores the year as a **plain scalar** (`:string`/`:integer` attr) instead of a `Components::Date`, the base `#exclude` **now nils that scalar directly** (the `:year` alias is additive — it keeps `:year` in the exclusion set as well as adding `:date`), so a lone-scalar-year flavor no longer needs an override. An `#exclude` override is required **only** when the scalar carries **sibling/derived attributes** the base can't reach — CSA's `year_format`/`year_prefix`/`original_year_4digit`/`french`, CIE's `date_separator` — in which case it must reset the **whole** cluster after `super` (else a bare ref fails to match a dated hit). ASHRAE's override (`lib/pubid/ashrae/identifiers/base.rb`, a lone `year` `:string` with no siblings, nil-ing `year` after `super`) is now redundant-but-harmless like BIPM's. ASHRAE's partial form additionally required two **parser** fixes: making the type keyword optional in the publisher branch, and excluding the literal `ASHRAE` from the standalone-copublisher `letter.repeat` (via `str("ASHRAE").absent?`) so `ASHRAE 15-2019` stops mis-routing as a copublisher. A no-type ASHRAE ref canonicalizes to the default `Standard` type (`ASHRAE 15` → `ASHRAE Standard 15`).

- **Flat scalar serialization of a degenerate component (`edition`, `date`)**: a component carrying only its single significant field serializes as that bare scalar, and the bare scalar is accepted back — `edition: "2"` rather than `edition: {number: "2"}`, `year: "2024"` rather than `date: {year: "2024"}`. This is the shape an index row wants to be read in, and the shape the metanorma mapping layer can write without knowing pubid's component classes (pubid#360 item 3). **The test is per IDENTIFIER, not per flavor, and that is the whole design.** One flavor's corpus holds both shapes: of 9,730 dated IEC identifiers, 9,728 carry a year alone but **10 carry a month** (`IEC CA 01:2025-10`, `IECEE 02:2025-06(en)`) and **2 are undated** (`IEC 60050:--`); a flavor-wide switch would have discarded those. Measured over the whole fixture corpus, flattening moves **607 IEC editions** (`number` is the only field the single construction site at `iec/builder.rb` ever sets) and **885 dates** (ansi 1, bsi 762, cen_cenelec 58, idf 64 — every one of them year-only). It deliberately does **not** move ISO's 11 editions (all carry `original_text`, e.g. `"Ed 13"`) or NIST's 1,746 (`type`/`id`/`original_prefix`), because those components are not degenerate. **The rule lives in ONE place** — `flatten_scalar_components` inside `Identifier#to_hash`'s canonicalizer and `inflate_scalar_components` in the class-level `from_hash` (`lib/pubid/identifier.rb`), driven by the `FLAT_SCALAR_COMPONENTS` / `FLAT_SCALAR_FIELDS` tables — not in per-flavor converters, so a flavor added tomorrow inherits it. The tables are read through the class methods `flat_scalar_components` / `flat_scalar_fields`, so a flavor can add an entry for its own classes only: CEN/CENELEC adds `publisher` and `copublishers` (a collection flattens to a list of scalars). Do not add `publisher` to the shared table without regenerating `relaton-data-ieee`, whose rows hold the nested `{"body" => …}` form (`lib/pubid/cen_cenelec/CLAUDE.md`). For a shape the tables cannot express, a class can override the class hooks `compact_hash(model, hash)` (called by the canonicalizer for every identifier, nested ones included) and `inflate_scalar_components` (its reverse on `from_hash`); CEN uses them to write a draft stage as one code (`"stage" => "pren"`). **Four guards, each of which was a real bug before it existed:** (1) `Lutaml::Model::Utils.empty?(nil)` is **false**, so a nil check is explicit — without it nothing ever looked degenerate; (2) a field whose value is itself a component is **never** flattened (ISO's edition `number` is a `Components::Code`), because the flat form would come back a String and break `from_hash(to_hash) == parse` — the silent `#matches?` inequality this file records as the costliest failure mode here; (3) inflation is skipped when the flavor declares its **own converter** for the flat key (`custom_methods` on the `key_value` rule — IEC's `year_from_kv`), but *not* for a plain `map "edition", to: :edition`, which hands the value to lutaml and cannot cast a String; (4) the `date`→`year` **rename** is skipped when `year` is itself a declared attribute — ~20 flavors (ASHRAE, ASME, CIE, CSA, JIS, OGC, IEEE …) model the edition as a real `year` attribute, and folding it into a `date` component silently dropped the year on every round trip. `from_hash` reads **both** shapes, so every published `relaton-data-*` row keeps deserializing; only rows that actually carry a nested `edition`/`date` see their `from_hash(h).to_hash == h` gate move. Locked by `spec/pubid/flat_scalar_serialization_spec.rb`, which asserts both directions on IEC — the flat case *and* the month/undated exceptions — and the legacy nested form for each flavor.

- **Constructor contract: scalars coerced, unknown keys refused**: `Identifier.new` now coerces a scalar into the component its attribute declares and **raises `ArgumentError` naming any key the class does not declare**, uniformly for every registered flavor (`normalize_init_attributes`, `lib/pubid/identifier.rb`; locked by the registry-driven `spec/pubid/attribute_construction_spec.rb`, modelled on `parse_error_spec.rb` so there is no per-flavor table to go stale). **The refusal is the important half.** lutaml reads only declared attribute names out of the hash (`Serialize#initialize_attributes`) and reports nothing about the rest, so `new(number: "1000", year: 2023)` returned an identifier with **no year at all and no diagnostic** — `year` is a READER over `date` on every date-based flavor, never an attribute. A dropped key is a silent wrong answer. Coercions are **type-aware**: `edition: 2` becomes a `Components::Edition` only where the attribute declares one (~16 classes declare a plain `:string` and keep the scalar), and `year:`/`month:`/`day:` fold into `date` only when the alias is not itself a declared attribute. **Safe to apply in the constructor because neither internal rebuild path routes attribute keys through it** — verified, not assumed: `from_hash` calls `new` with *no* attributes and assigns through setters afterwards (`initialize` sees only `[:lutaml_register]`), and `#exclude` rebuilds from `self.class.attributes`, so only declared names by construction. Two hooks make it extensible: `RESERVED_INIT_KEYS` (lutaml's own `:lutaml_register`) and a per-flavor `self.extra_init_keys`, which IEEE overrides for its runtime-only `code`/`draft`/`draft_obj` ctor params. **The two flavors whose `initialize` calls `super()` with no attributes and hand-loops setters — IEEE and NIST (ITU already routes through the base) — must call `normalize_init_attributes` themselves**, or they silently opt out of the contract. **The refusal earned its keep immediately: it exposed three silent data-loss bugs no test covered**, because in each the output merely came out *shorter*, never wrong. CIE's builder assembled one attribute hash for every CIE type and always set `s_prefix`, which only 3 of its 8 types declare — 94 identifiers stopped parsing the moment surplus keys were refused (`lib/pubid/cie/CLAUDE.md`). IEEE's `build_aiee_asa_adoption` passed `adopted_identifier:` where the class declares the collection `adopted_identifierS`, so the ASA half of 13 historical ids was never stored (`AIEE No 18-1934 (ASA C55 1934)` rendered back as `AIEE No 18-1934`) — and the fixture had recorded the correct output all along, so code and fixture had silently diverged. IEEE's `CsaDualPublished` declares `csa_identifier` as a deliberate non-lutaml `attr_accessor`, which its hand-rolled `initialize` loop never assigned, so the renderer read nil and `IEEE Std 844.1-2017/CSA C22.2 No. 293.1-17` rendered as `IEEE Std 844.1-2017/CSA` (`lib/pubid/ieee/CLAUDE.md`). **A non-attribute constructor parameter needs BOTH halves** — `extra_init_keys` so the check admits it, and an assignment path so it is actually stored; declaring only the first gives you a key that is accepted, ignored and lost. **The coercion reaches a component-typed COLLECTION too, and that half was the residue** — `coerce_component_scalars` walked the two-entry `FLAT_SCALAR_FIELDS` whitelist (`edition`, `date`) and had no Array branch, so `languages: ["en"]` and `copublishers: ["ISO"]` stored raw Strings that then **raised** — `to_s` with `wrong number of arguments` (`Language#to_s(lang_single:)`) and `to_urn` with `undefined method 'code'`/`'body'`. It is a coercion gap, not a lutaml limit: lutaml casts a Hash element into the component and passes a String through untouched, so `languages: [{code: "en"}]` already worked. `DEGENERATE_COMPONENT_FIELDS` now keys the wrap by component **CLASS** rather than attribute name (`Components::Language => :code`, `Components::Publisher => :body`), which is what makes one entry cover a scalar attribute, a collection (an attribute reports its ELEMENT class) and a flavor subclass (`Pubid::Iec::Components::Publisher`, matched with `<=`). **`Components::Code` is deliberately absent, and that exclusion is pinned by a spec**: a String left in `number` renders and serializes correctly today, so coercing it would buy nothing and would turn `to_hash` from `{"number" => "1000"}` into `{"number" => {"value" => "1000"}}` on the six flavors that still declare a Code (iso, iec, nist, csa, sae, ccsds) — an index wire-format change, and one the `number` retype tranches sequence to land last. The rule of thumb the two entries encode: **coerce a component that RAISES on a String, leave one that merely stores it.** Verified by replaying a captured `main` baseline of all 99,019 pass-fixture identifiers across every flavor — `to_s`, `to_urn`, `to_hash`, `root.number` and the identifier class byte-identical, 0 differences, which is the invariant to expect: every shape this repairs raised before, so nothing that already worked could move.

- **Uniform annotated rendering (`to_s(annotated: true)`)**: annotation wraps each sub-token of a rendered identifier in a semantic `<span class="…">` for downstream CSS (isodoc's `std_docid_semantic_parse`). In pubid 1.x it was applied in **one line** of the shared core (`pubid-core`'s `Renderer::Base#prerender_params` wrapped every value in the param hash), so all 40-odd flavors got it free; pubid 2 replaced that hash with typed components and per-flavor renderers and the annotation went with it. `Renderers::Base#annotate` survived but **only the `HumanReadable` family calls it** — all 39 flavor renderers receive `context.annotated` and ignore it. Two seams now close the gap. **(1) `Renderers::Annotator`** recovers the markup from the outside: it asks the identifier for its own component values and wraps each where it appears in the rendered string, so one implementation covers every flavor including ones added later. It is a **fallback, not a replacement** — applied only when the renderer emitted no `<span` of its own, so ISO's exact render-time placement still wins. Tokens are matched left-to-right behind a cursor and **sorted by where they actually appear**, not by a fixed idea of layout: ISO prints the number before the type (`ISO/IEC TR 2131`), CCSDS after (`CCSDS 121.0-B-2`), and declaration order pushed the cursor past CCSDS's number. A token that does not appear verbatim is skipped — a missing span beats a wrong one. **(2) Every identifier `to_s` accepts the flag.** That was the bigger half: `to_s` is defined 62 times in incompatible shapes, and **37 classes across 6 flavors REJECTED `annotated:` outright** — 25 (CIE, CSA, ITU, CCSDS, GOST) declare no parameters at all and raised `wrong number of arguments (given 1, expected 0)`, IEEE's `JointDevelopment` had a closed keyword list, and NIST's 11 take a positional `format`. A raise is worse than a missing span, because a wrapper is exactly the shape a consumer renders. All 37 now accept it, asserted directly over every loaded class by the spec rather than through one example. A `to_s` that composes its string by hand instead of calling `render` (ITU, CCSDS, NIST) never reaches the choke point, so it applies `annotate_plain_render` on the way out. **This is deliberately a per-class opt-in, and the alternative was tried and rejected**: a module prepended to every subclass via `inherited` normalises all 62 signatures in one place and reached 214 annotating types with 0 raises — but putting it into ~500 ancestor chains correlated with a GOST render of `ISO TR …` instead of `ISO/TR …` under full-suite load — traced to an unrelated routing race, not the prepend (`lib/pubid/gost/CLAUDE.md`). That is the multi-flavor nondeterminism this file documents elsewhere, and the lesson is blunt: **do not insert a module into every identifier's ancestor chain in this codebase**, however clean it looks — an explicit call in the handful of classes that need it changes no chain and cannot have that effect. **Measured over one identifier of every concrete type: 228 of 229 annotate, 0 raise, 0 strip-mismatch** (against 4 annotating and 13 type-families raising before this work, then 193 after the first half). The 36 that reached the second half were **not one problem but three**, and the distinction is the useful part — the hand-off assumed all 36 needed the same one-line call, and 3 of them did not.
**(a) 34 needed the call.** Their `to_s` composes its own string, so `annotate_plain_render` goes on the way out: 10 CIE types, 5 CSA wrappers, 8 IEEE (AIEE, IRE, `JointDevelopment`, and all five `Nesc::` classes — the four subclasses do not call `super`, so annotating `Nesc::Base` alone would have covered only `Edition`), 5 ITU supplements, 2 CCSDS and 8 NIST. **Where the body has early returns the composition moves to a private `render_plain` and `to_s` becomes two lines** — CIE `Standard` (3 exits) and NIST `SupplementIdentifier` (4). Watch two traps there: a bare `private def` is a rubocop offence, but converting it to a `private` **section** silently privatises every method BELOW it (this made CIE `Standard#mr_type`, which the MR renderer calls, private), so the section goes at the end of the class; and `super` is not reachable from a private method, so `SupplementIdentifier` hands it in as a block (`render_plain(format) { super(format) }`).
**(b) 2 were value-match misses, and the fix is a hook, not a call.** CSA `Cec` and IEC `WorkingDocument` already reached the choke point inside `render` — they came out plain because the annotator found none of their component values in the string. `Pubid::Identifier#annotation_tokens` returns `Renderers::Annotator::TOKENS` and a class **appends** its own: `WorkingDocument` keeps its identity in `technical_committee`/`wd_number`/`wd_stage`, and `Cec` stores the joined `"C22.2-286"` in `number` while printing the two halves it holds in `cec_part`/`no_number`. Appending rather than replacing costs nothing — a token whose value is not in the string is skipped anyway. **The 6 CSA and CIE wrappers looked like this too and were NOT**: a wrapper prints the document it wraps, so its tokens are on `base`, and `Annotator#emit_tokens` now walks `base` / `ids` / `identifiers` recursively (capped at `MAX_NESTING`, so a cyclic `base` cannot hang a render). That one change fixed 6 of the last 8; only then were the remaining 2 identifiable as genuinely needing named attributes.
**(c) 1 cannot be annotated by a value-matching design, and stays plain deliberately.** ASTM `TechnicalReport` prints `ISO/ASTMTR52952-EB` — no separators — so although it carries publisher `"ISO/ASTM"` and number `"52952"`, both sit against a word character and `Annotator#standalone?` refuses them. That refusal is the rule that stops the part `1` of `ISO 1234-1` binding inside `1234`; relaxing it for one flavor would loosen it for all. A spec asserts it stays plain, so a change that annotates it turns red and asks why.
**A `to_s` that post-processes an annotated string must post-process FIRST.** NIST's `Circular` and `Handbook` did `result = super` — which annotates — then rewrote the edition with a **`$`-anchored** regex; once the string ends in `</span>` the anchor cannot match and the rewrite silently stops applying. Both now strip the flag before `super`, rewrite, then annotate. **This is exactly the kind of defect an output assertion cannot catch**: for both fixture references the annotator happens to match only the leading publisher, so the tail is bare and the old order still produced the right answer. The spec therefore asserts the **ordering** — it wraps `annotate_plain_render` and checks that the string handed to it is already rewritten and carries no span — and it was verified to fail when the order is reverted. The same read-then-rewrite shape is in CSA `CsaAdopted` (regex over `base.to_s`); it is safe only because the wrap goes on the outside. Locked by `spec/pubid/annotated_rendering_spec.rb`, whose acceptance check **force-loads the whole class tree two levels deep** — a shallow scan reported IEEE's `Nesc::`/`Ire::` families clean while all six still raised; the ISO-only `spec/pubid/iso/renderer/annotated_spec.rb` still guards the native path. **When adding a `to_s` to an identifier class, give it `**opts`** — the spec above fails otherwise — **and call `annotate_plain_render` on its result if it does not go through `render`.**

- **Prefix routing (`Pubid.parse`) and cross-flavor stage lookup (`Pubid.locate_stage`)**: `Pubid.parse(string)` used to raise `No flavor specified` for **any** human-readable string, so a reference whose flavor the caller did not already know could not be parsed at all — and pubid 1.x's `Pubid::Registry.parse`, which isodoc still calls, was gone. It now routes over the existing `Pubid.prefix_flavors` table, **longest matching prefix first** (so `ISO/IEC 2131` is not handed to the flavor that merely owns `ISO`) and at a token boundary (so `ISO` does not claim `ISOFIX`), then falls back to every flavor in registry order; on total failure it raises `Parslet::ParseFailed`, the class the uniform parse-failure contract requires. `Pubid::Registry.parse` delegates to it — one implementation, not two. **The MR-string branch now falls through to prefix routing when the MR parse fails**, because `FormatDetector` is a shape heuristic (`/\A[A-Z]{2,}[.-]/`) and some human-readable identifiers have that shape — `ITU-T G.711` is the standing example, and it reported an MR error for a string that was never an MR string. **Three hazards the routing had to be measured against, none of which a unit test would have shown:** (1) the candidate loop rescues **only `Parslet::ParseFailed`** — a blanket `rescue StandardError` swallowed the very `ArgumentError: unknown attribute…` the constructor contract raises, so a real builder defect in any flavor would have read as "this string is not an identifier"; (2) `Pubid::Parsers::MrString.detect_flavor` falls back to `:iso` for an unknown publisher and `Pubid::Iso.parse` sends an MR-shaped string straight back to it, so a string whose conversion is a **fixed point** recursed until the stack blew — `Pubid::Iso.parse("ECMA-426 ed1")` raised `SystemStackError` on `main`, and 41 fixture ids hit it through routing; the fixed point now raises `Parslet::ParseFailed`, which is both true ("never was an MR string") and the class routing needs to try the next flavor; (3) `adobe` and `iana` accept **any slug by design**, so whichever came first in registry order claimed every otherwise-unmatched string and answered with structure the input never had (`iec.60050` → `IANA iec.60050`). Routing therefore prefers a parse that **round-trips exactly**, and lets **only a prefix owner** supply a non-exact fallback — an anything-goes flavor never owns a claim, and a grammar that parses a string only by defaulting what the input never spelled does not supply one either (iec's grammar takes `CIE` as a number and its builder defaults the `IEC` publisher, answering `IEC CIE`; astm answered `123` with `ASTM 123`) — those flavors are found by **probing** with a meaningless string (`accepts_anything?`), not by a hardcoded list, so a grammar that gains or loses that property is classified without anyone editing a constant. The round trip is a preference and not a requirement because several flavors legitimately normalise on render (OGC prints `06-121r9` for `OGC 06-121r9`); requiring it cost 32 correct ASHRAE/ASME/CSA/IEEE routes. Measured over a 5,769-id corpus sample: **5,712 routed to the owning flavor, 0 rejected, 0 raised**. `Pubid.locate_stage(abbr, flavor: nil)` closes the other half of pubid#360: each of the 44 flavor modules memoises `all_typed_stages` over its own namespace, so `Pubid::Iso.locate_stage("ADTS")` was nil while `Pubid::Iec.locate_stage("ADTS")` found it. With `flavor:` it delegates; without, it searches every flavor via `each_stage_flavor_module`, which skips the three that define no stages (adobe, easc, gost) and collapses the `:cen`/`:cen_cenelec` alias by module identity, as `each_prefix_flavor_module` does. `Pubid.locate_stage_flavors(abbr)` names the owners. **The return type is documented as "the flavor's typed-stage object", not a class** — IEEE's `Ieee::Components::TypedStage` is not a subclass of the shared component. **isodoc still needs its own change**: it rescues `Pubid::Core::Errors::ParseError`, which does not exist in pubid 2, so the rescue clause itself raises `NameError` (hand-off `riboseinc__isodoc__pubid2-registry-parse-and-error-class`).
- **`Pubid.from_hash` — the hash counterpart of `Pubid.parse`**: `Pubid.from_hash(data)` (`lib/pubid.rb`) builds the concrete identifier class from a serialized hash without a flavor name. It takes the identifier hash — a `to_hash` result, or the `:id` value of a relaton-data `index-v2.yaml` row — not the whole row. The routing information is `_type` (`pubid:<flavor>:<type>`), so there is **no prefix guessing**: `Pubid::TypeResolver.resolve` names the class and that class's polymorphic `from_hash` does the rest, nested cross-flavor ids included. `Pubid::Registry.from_hash` delegates, as `Registry.parse` does. **Why it exists when `Pubid::Identifier.from_hash(h)` already dispatches by `_type`**: that path fails on a hash with no `_type`, or an unknown one, with an obscure `Lutaml::Model::InvalidFormatError` (`undefined method 'key?'`); `Pubid.from_hash` raises `Pubid::Errors::InvalidInputError` (an `ArgumentError`, rescuable as `Pubid::Errors::Error`) that names the problem. It does not wrap an error from the class's own `from_hash` for a well-formed `_type` — that is a flavor defect and propagates. Measured over ~22,000 sampled rows of all 27 published `index-v2.yaml` files: the right class and an equal `to_hash` for 26 files. **IHO's `index-v2.yaml` is a legacy pre-pubid-2 shape with no `_type`** (`publisher`/`type`/`version` symbol keys), so every IHO row raises `InvalidInputError` until that index is regenerated; OIML shows a `to_hash` asymmetry that exists without this method. Locked by `spec/pubid/from_hash_spec.rb`, whose per-flavor sample table has meta-examples that fail when a registered flavor has no entry.

- Fixture files in `spec/fixtures/` — one identifier per line in `pass/` and `fail/` directories
- **`spec/spec_helper.rb` forces `Encoding.default_external = Encoding::UTF_8`.** Fixture files legitimately contain non-ASCII bytes (e.g. em/en dashes). Without this, `File.read`/`File.readlines` default to the process locale (`LANG`/`LC_ALL`), which is `US-ASCII` in a locale-less container/CI runner and raises `Encoding::CompatibilityError` the moment a fixture line with such a byte is read — this previously aborted the whole RSpec load phase (9 spec files failed to load before a single example ran) and broke the shared `FixtureFileHelper` the same way. `.rspec` already does `--require spec_helper`, so this one line covers `rake test:all` and any targeted `bundle exec rspec spec/pubid/<flavor>/...` run alike.
- **Fixture files are generated, and the lines are not all plain identifiers.** `spec/fixtures/classify_fixtures.rb` (driven by `bundle exec rake "validation:classify[<flavor>]"`) reads **only** `identifiers/full/*.txt`, then **`rm -rf`s `pass/` and `fail/`** and rebuilds them from the live parser. It writes three line shapes: a plain identifier (byte-exact round-trip), `!input!rendered` in `pass/` (a *normalizing* parse — it succeeds, but `to_s` differs from the input), and `#input# ErrorClass: "message"` in `fail/`. Two consequences. **(1)** A fixture spec that does not split the markers feeds `!input!rendered` to the parser verbatim and counts a spurious failure; `FixtureFileHelper#read_pass_fixture_entries` / `#read_fail_fixture_inputs` (`spec/support/fixture_file_helper.rb`) do the splitting, and their regexes deliberately mirror the writer's so the two cannot drift. Note `read_fixture_file` drops every `#`-leading line, so it returns `[]` for a `fail/` file. **(2)** Anything hand-added to `pass/` but absent from `full/identifiers.txt` is **deleted** by the next classification run — CSA nearly lost the three partial-reference fixtures from PR #134 this way. Add a new fixture to `full/identifiers.txt` and regenerate; **never hand-edit `pass/` or `fail/`**.
- **A fixture spec whose glob is wrong reports 0 examples, not a failure.** `__dir__` in `spec/pubid/<flavor>/` is **two** levels below `spec/fixtures/`, and the flavor directory is **lowercase**. The historical `../../../fixtures/<FLAVOR>` spelling gets both wrong: the extra `..` points at a non-existent repo-root `fixtures/`, and the uppercase name resolves only on a case-insensitive filesystem (so it would still run 0 examples on Linux CI). ITU, CSA and CEN/CENELEC are fixed; **nine flavors still carry it** (amca, api, ashrae, asme, astm, bsi, idf, jcgm, oiml). `spec/pubid/csa/fixtures_spec.rb` is the reference shape: a **tripwire** example asserting the globs are non-empty (the only thing that makes this defect loud), zero-failure per-file examples over `pass/` **and** `fail/` instead of a 90% threshold, and a **conservation** example asserting the inputs across `pass/` + `fail/` equal those in `full/identifiers.txt` — which is what catches a half-written classification run or a `pass/`-only fixture. (hand-off: ten-dead-fixture-specs.)
