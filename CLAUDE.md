# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

PubID is a Ruby gem for creating interoperable identifiers for standards documents (ISO, IEC, NIST, IEEE, etc.). The codebase lives in a single gem with all flavors under `lib/pubid/{flavor}/`. There are 22+ supported flavors.

## Common Commands

```bash
# Install dependencies
bundle install

# Run all tests
bundle exec rake test:all

# Run integration tests (cross-flavor)
bundle exec rake test:integration

# Run the default suite (test:all + test:integration)
bundle exec rake

# Lint all code
bundle exec rake rubocop        # rubocop:all is an alias

# Build the gem (into pkg/)
bundle exec rake build

# Version management (version lives in lib/pubid/version.rb)
bundle exec rake version:show                     # Show gem version
bundle exec rake version:bump[patch|minor|major]  # Bump version

# Validation (per-flavor parser accuracy)
bundle exec rake validation:report             # Summary for all flavors
bundle exec rake validation:classify[iso]      # Classify one flavor's results
bundle exec rake validation:classify_all       # Classify all flavors
```

For running specific test files during development, use rspec directly:

```bash
bundle exec rspec spec/pubid/iec/identifiers/technical_report_spec.rb
bundle exec rspec spec/pubid/iso/              # all ISO tests
```

## Architecture

### Parse Pipeline

```
Input String
    │
    ▼
Pre-parser Normalization (data/{flavor}/update_codes.yaml)
    │
    ▼
Parser (Parslet PEG grammar → parse tree)
    │
    ▼
Builder (parse tree → attribute hash)
    │
    ▼
Identifier (Lutaml::Model object → to_s / to_urn / to_h)
```

### Flavor Module Structure

Each flavor under `lib/pubid/{flavor}/` follows:

```
lib/pubid/{flavor}/
├── parser.rb          # Parslet PEG grammar
├── transformer.rb     # AST → attribute hash (some flavors)
├── builder.rb         # Parse tree → identifier object
├── scheme.rb          # Identifier type registry (some flavors)
├── identifier.rb      # Top-level entry point (parse method)
├── identifiers/       # Type-specific classes (e.g., international_standard.rb)
├── renderer/          # Output formatting (some flavors)
├── urn_generator.rb   # URN output (most flavors)
└── urn_parser.rb      # URN input (ISO, IEC)
```

### Key Patterns

- **Parslet PEG parsers**: Each flavor defines grammar rules in `parser.rb`
- **TypedStage**: `Pubid::Components::TypedStage` with attributes: name, type_code, stage_code, abbr, harmonized_stages. Defined as `TYPED_STAGES` arrays on identifier classes.
- **Scheme class**: Some flavors (IEC, ISO) use a `Scheme` class as a registry for identifier types and typed stages
- **Lutaml::Model**: Serialization framework for identifier objects (`to_h`, `to_json`, custom mappings)
- **Canonical `to_hash` (no defaults)**: `Pubid::Identifier#to_hash` drops any attribute whose value is empty or equal to its default, so the serialized hash is a pure function of the identifier's values — `parse(s).to_hash`, `from_hash(h).to_hash`, and a manually-built id all agree, and the round-trip is idempotent (`from_hash(x.to_hash).to_hash == x.to_hash`). relaton-index relies on this exact equality to validate stored rows. The canonicalizer **recurses into nested components/identifiers** (`canonicalize_hash`/`canonicalize_nested`), because lutaml serializes a nested `Components::*` via its own transform — not the component's public `to_hash` — so a nested defaulted attribute (e.g. `Components::Supplement#has_revision`, default `false`) would otherwise leak into the parent hash. This works because pubid never consults lutaml's `using_default?` tracking and defines no `render_default: true` mapping; **do not** add a `render_default: true` mapping (it would need a default-valued attribute serialized, which `to_hash` now strips) without revisiting this invariant.
- **Compact flavor `key_value` mappings (ISO/JCGM/OIML/ETSI/ITU)**: flavors that want a flat, index-friendly hash declare a `key_value do … end` block that collapses `Components::*` to bare scalars — e.g. ETSI serializes a top-level `number` (plus a `parts` array, omitted when empty), `Version` as a scalar `version` + an `is_edition` boolean (omitted when false), and `Date` as top-level `year`/`month`/`day`. **Note for ETSI and OIML the flat keys are now real attributes, not converters reading through a `code` component** — see the ETSI/OIML index-key bullet below; the emitted hash is unchanged, but `map "number", to: :number` replaced `number_to_kv`/`number_from_kv`. The constant `publisher` ("ETSI") is intentionally **unmapped** and reconstructed from its attribute default, so it never bloats a row. **Placement matters when a flavor has a supplement/wrapper subtype that *delegates* attributes to an inner id**: ETSI's `SupplementIdentifier` (Amendment/Corrigendum) delegates `type`/`code`/`version`/`date` to its `base`, so the standard block lives on the **leaf `EtsiStandard`**, not the shared `Identifier`/`Base` — a block on the shared parent would be inherited-and-merged by the supplement and re-emit every delegated field at the top level (the old redundant shape). The supplement declares its own minimal block (`_type` + ordinal `number` + nested `base`), reconstructing `base` via `Pubid::Etsi::Identifier.from_hash` (a bare polymorphic cast would rebuild a plain `Base` and lose the concrete subclass). The per-flavor helpers (`emit_kv`, `date_for`, `year_to_kv`/…) are currently duplicated across jcgm/oiml/etsi by convention — mirror an existing flavor when adding another. **ITU** follows the ETSI pattern: the shared converter helpers live once on `Pubid::Itu::Identifier` (`identifiers/base.rb`), and the leaf standard block is installed via the `Identifiers::StandardSerialization` mixin (an `included` hook — lutaml **merges** a mixin-installed block with a second in-class `key_value` block, so `Question` adds `study_group`/`has_bl`/`bracketed`/`has_colon` and `CombinedIdentifier` adds `combined` on top). Leaf placement is load-bearing here too: `Supplement` (parent of `Amendment`/`Corrigendum`/`Errata`) and `Annex` declare their **own** minimal blocks with a nested-but-flat `base` via `Pubid::Itu::Identifier.from_hash`; a shared-parent block would make them re-emit `base`'s fields. **ITU supplement edge case:** the supplement copies `sector`/`series` from its base, so its block emits them **only when `base` is nil** (the series-only `ITU-T H Suppl. 1` form) via `supplement_sector_to_kv`/`supplement_series_to_kv` (guard `model.base.nil?`) — otherwise they duplicate the base.
- **`exclude` recurses into nested identifiers**: `Pubid::Identifier#exclude(*attrs)` (and the `:year`→`:date` alias) nils the named attributes and rebuilds via **`self.class.new(**attrs)`** (a keyword splat — issue #289). **The `:year` alias is additive, not a substitution** — `exclude(:year)` keeps `:year` in the exclusion set **and** adds `:date` (`excluded_args << :date if excluded_args.include?(:year)`, *not* `.delete`), so the attribute loop nils **whichever name the flavor actually declares**: `date` for a year-in-`Components::Date` flavor (ISO/ITU/…), a plain `year` attribute for a lone-scalar-year flavor (GOST/astm/asme/api/ogc/easc/jis). This means a flavor whose edition is a **lone `year` scalar with no format siblings needs no `#exclude` override at all** — the base handles it (GOST issue: `exclude(:year)` was a silent no-op before this, because the old `.delete(:year)` dropped `:year` and mapped only to the non-existent `date`). The mapping is one-directional (only `:year` adds `:date`; `exclude(:date)` never adds `:year`), so a plain `year` always survives a date-only exclusion. The `**attrs` keyword splat is what makes the rebuild work for every flavor whether its identifier `initialize` is positional (the base `initialize(attrs = {}, options = {})`) or **keyword-only** (ITU `**kwargs`, IEEE `**args`, NIST `**attributes`). Under Ruby 3 kwarg separation the earlier positional `self.class.new(attrs)` raised `ArgumentError` for every keyword-init flavor, breaking `#matches?` (which calls `exclude`) — so **do not** revert this to the positional form. (One laggard remains: AMCA `Publication`/`Interpretation` use a *named*-keyword `initialize` with non-attribute ctor params, so the attribute-hash rebuild can't reconstruct them — they still need their own `exclude` override.) Any attribute value that *is* (or is a collection of) another `Pubid::Identifier` is passed through `exclude_from_nested`, which re-applies the same exclusion to the inner identifier. This is what makes `exclude(:date)` actually drop the publication date on wrapper types (BSI `AdoptedEuropeanNorm`/`ConsolidatedIdentifier`/`ExpertCommentary`, and any flavor that delegates `date` to an inner id) instead of nilling an unused outer attribute. Components and scalars are copied verbatim — only real `Identifier` instances recurse — so flat identifiers (ISO, IEC …) are unaffected. **ETSI and ITU override `exclude_from_nested`** to reach a part stored *inside* a Code component: both keep number+part in one `Components::Code`, so excluding `:part`/`:parts` returns a Code copy with `parts: []` (keeping the number/series), letting a part-less reference match every edition via `matches?(other, ignore: [:parts])` (ITU editions `P.838` ↔ `P.838-3`). **BIPM also overrides `exclude`**: it stores the publication year in its own `year` integer attribute (not a `Date` component); the base now nils that `year` directly (it's an attribute), so BIPM's override — calling `super` then re-nil-ing `year` — is now *redundant but harmless* (both set `nil`); it is kept to avoid churn. A partial (date-less) BIPM ref is a year wildcard under `matches?(row, ignore: [:year])`. **CSA follows the same scalar-year pattern** (`Csa::Identifier#exclude`): its `year` is a plain `:string`, but unlike BIPM the year carries *format metadata* stored in sibling attributes (`year_format`, `year_prefix`, `original_year_4digit`, and `french` — the last set **only** from a `:F` year prefix, the French-edition form `CSA B149.1:F20`). A year-less parse leaves all of these nil/false, so the override must reset **every** year-derived attribute (not just `year`) after `super`, or `==` — and thus `matches?` — would still diverge (e.g. a bare `CSA B149.1` would fail to match the French edition `CSA B149.1:F20`). The `respond_to?(:year=)` guard skips the adoption wrappers (`CanadianAdopted`/`CsaAdopted`), which delegate year to a nested inner id and lack a `year` accessor — those are handled by the base recursion. **Lesson for any future scalar-year flavor**: the base already nils a lone `year` scalar, so an `#exclude` override is needed **only** when the year has sibling/format attributes (CSA's `year_format`/`year_prefix`/`original_year_4digit`/`french`) or a differently-named scalar cluster (IEEE's `year`/`month`/`day`) that the base can't reach — and then it must reset the *whole* cluster, not just the year scalar. A lone `year` with no siblings (GOST/astm/asme/api/ogc/easc/jis) needs no override.
- **Uniform parent accessor (`base`) and `#root`**: a wrapper/supplement identifier exposes the document it wraps under a single attribute named **`base`** (polymorphic `Pubid::Identifier`). This name is uniform across *every* flavor — the earlier split where some flavors used `base_identifier` and others `base` was collapsed by renaming `base_identifier` → `base` everywhere (Ruby attribute/method **and** the on-disk serialization key). `#root` (`lib/pubid/identifier.rb`) walks `base` recursively to the origin document: `base ? base.root : self`; a plain standard (`base` nil) is its own root. **Wrappers that store members in an `identifiers` collection instead of `base`** — `ConsolidatedIdentifier` (iec/bsi/cen_cenelec) — override `#root` to walk `identifiers.first.root`. **CSA's container types** (`WrapperIdentifier`/`CompositeIdentifier`/`Bundled`/`Combined`) used to descend from `Lutaml::Model::Serializable` and define `def root; self; end`; they are now real `Pubid::Csa::Identifier` subclasses carrying a polymorphic `base` (see the CSA bullet in `docs/flavors/csa.md`), so the first three inherit `#root` and only `Combined` overrides it, walking its `identifiers` collection. The registry-driven `spec/pubid/root_spec.rb` locks this. **relaton note**: relaton-* consumed the old `.base_identifier`; they must migrate to `.base` (no alias is kept), and flavors whose on-disk key changed from `base_identifier` → `base` (cen_cenelec, cie, nist, idf, ieee, bsi, plateau, ashrae, iala, oiml) need their `relaton-data-*` indexes regenerated. **Index-key corollary — every leaf must have a non-empty `number`**: relaton-index keys its binary-search narrowing on `root.number` (a wrapper files under its origin standard's number; a leaf is its own root). So **every** identifier that can be a `root` must expose a non-empty `number`, including non-`Standard` leaves — CIE proceedings papers store the paper string as `number` (`"OP02"`; the x-form's conference is a separate `conference_number`), and CIE `TutorialBundle` mirrors its ordinal into `number`. A comma-list `Bundle` instead models its members as `ids` (a polymorphic `Identifier` collection, mirroring IEC's `ConsolidatedIdentifier`); since a CIE bundle is the parts of one supplement of one standard, the shared `base` is hoisted to the bundle (each id keeps only its differing supplement `number`/`part`) and `#root` walks that `base` — so it keys via the members' origin standard and needs no stored `number`. (The builder falls back to per-id bases if members ever don't share one; not seen in practice.) A leaf with a nil `number` yields the empty key `""` and silently defeats the binary search. `spec/pubid/cie/index_number_spec.rb` locks `root.number` non-empty for every CIE type.
- **Uniform per-flavor handle (`Pubid::<Flavor>::Identifier`, not `Identifiers::Base`)**: every flavor's canonical, public handle is the class **`Pubid::<Flavor>::Identifier`** — a real `::Pubid::Identifier` subclass that is the common ancestor of *all* that flavor's concrete types (including wrapper/supplement subtypes) and the host of the shared polymorphic `from_hash`. It is the class to pass anywhere a flavor's identifier class is needed (e.g. relaton-index's `pubid_class:`); `Pubid::<Flavor>::Identifier.from_hash(h)` dispatches to the right concrete subtype by `_type` regardless of receiver. The legacy `Pubid::<Flavor>::Identifiers::Base` name survives **only** where it is still a genuine *intermediate* class carrying shared "single-document" attributes that wrapper subtypes deliberately bypass — **Category B: `iec, asme, api, astm, csa, ccsds, cen_cenelec`** (there `Base < SingleIdentifier`/`< Identifier`, an internal implementation class, *never* the public handle: it is narrower than `Identifier`, excluding wrappers). Every other flavor (**Category A**) used to define `Identifiers::Base = Identifier` as a pure alias; that alias is now **removed** — `Identifiers::Base` is undefined there and code must use `Identifier`. Two cross-flavor specs lock this: `spec/pubid/identifier_hierarchy_spec.rb` (Category-A `Identifiers::Base` undefined, Category-B present-and-distinct) and `spec/pubid/uniform_identifier_handle_spec.rb` (`from_hash(x.to_hash).to_hash == x.to_hash` through the `Identifier` handle for every flavor, wrappers included). **Landmine**: bare `Base` inside a flavor can mean an *unrelated* nested class — `Pubid::Nist::Series::Base` (`nist/series/*`) and `Pubid::Ieee::Identifiers::Nesc::Base` (`ieee/identifiers/nesc/*`) — so never blanket-rename `Base`. **relaton note**: consumers passing a Category-A `Pubid::<Flavor>::Identifiers::Base` (e.g. IHO crawler `pubid_class:`) must migrate to `Pubid::<Flavor>::Identifier`; NIST/IEC crawlers already do.
- **Matching primitives (`base_document` / structural `exclude` / `matches?`)**: `Pubid::Identifier` exposes the vocabulary relaton uses to match a reference against catalogue hits without regexes. `#base_document` returns the wrapped standard with amendment / corrigendum / Expert-commentary / Flex-version layers peeled recursively (base case returns `self`; wrappers override it, delegating to `base`/`identifiers.first`). `#exclude` also accepts the **structural** keys `:amendment`/`:supplement` (reduce one supplement layer via `#drop_supplements`, which `ConsolidatedIdentifier`→`identifiers.first` and `Amendment`/`Corrigendum`→`base` override) alongside attribute keys like `:date`/`:edition`. `#matches?(other, ignore:)` is just `exclude(*ignore) == other.exclude(*ignore)`. BSI `Amendment` and `Corrigendum` share a class-agnostic supplement interface — `supplement_type`/`supplement_number`/`supplement_year` — so callers never special-case corrigenda.
- **Flavor prefix routing (`Pubid::<Flavor>.prefixes`)**: every registered flavor exposes a uniform, static `prefixes` class method returning `Array<String>` of the **leading identifier prefix tokens** it recognizes (the tokens a printed id can start with), used by relaton to route a reference string to the owning SDO. A flavor gets this by `extend Pubid::PrefixesSupport` (`lib/pubid/prefixes_support.rb`) and defining a frozen `PREFIXES` constant holding **only its own** tokens, sourced from the parser grammar/constants (e.g. IEC derives from `Components::Publisher::PUBLISHERS.keys`). Joint/co-publication tokens (`ISO/IEC`, `ISO/IEC/IEEE`, `ANSI/ASHRAE`…) live **only** in the central `Pubid::JOINT_PREFIXES` map in `lib/pubid.rb` and are merged in by the mixin, so a co-published prefix appears **symmetrically** in every co-publisher's list without hand-duplication. Top-level helpers: `Pubid.prefixes(:iso)` and `Pubid.prefix_flavors` (reverse index `{ "ISO/IEC" => [:iec, :iso], … }`, which de-dups the `:cen`/`:cen_cenelec` alias by module identity). **Inclusion policy** (documented in the mixin's YARD): include publisher prefixes and leading series/type tokens that can *begin* a reference (BSI `DD`/`PD`, NIST `FIPS`); **exclude** pure sub-series that never lead a reference and ambiguous single letters (BSI aerospace `A`/`B`/`C`). When adding a new flavor, `extend Pubid::PrefixesSupport` and define `PREFIXES` (the cross-flavor spec `spec/pubid/prefixes_spec.rb` asserts every registered flavor responds).
- **A `collection: true` attribute needs `initialize_empty: true`, or the two construction paths disagree**: `Pubid::Tgpp::Identifier#parts` was declared `collection: true` with no default. `Builder#build` always passes `parts: extract_part_strings(…)`, which returns `[]` when the grammar matched no part, so a **parsed** part-less identifier held `[]`; the serialized hash carries no `parts` key at all, so `from_hash` never set the attribute and a **deserialized** one held `nil`. The two were therefore not `==`. **Why that is a silent, high-blast-radius bug rather than a cosmetic one**: `#matches?` is `exclude(*ignore) == other.exclude(*ignore)` and `#exclude` rebuilds through `self.class.new(**attrs)`, so the `[]`/`nil` difference survives the exclusion and every *matching* call fails too — and it fails by returning `false`, so a relaton index lookup (parsed user reference vs `from_hash`-ed index row) just returns nil with no error. Measured on `relaton/relaton@feat/3gpp-consume-index-v2`: **366 of 387** fixture rows failed to match — precisely the part-less ones, while the 21 parts-carrying rows matched because both sides then held `["04", "1"]`. The fix is `attribute :parts, :string, collection: true, initialize_empty: true` (`lib/pubid/tgpp/identifier.rb`). **`initialize_empty: true` is the preferred spelling for this from now on**, and it is not a second mechanism: lutaml's `Attribute#set_default_for_collection` desugars it to `@options[:default] ||= -> { build_collection }`, i.e. *exactly* the `default: -> { [] }` that `Ieee::Identifiers::CodeNumber` / `IecIeeeCopublished` / `Itu::CombinedIdentifier` already use (verified identical on `default_set?`, `default`, `to_hash`, `==`, and per-instance array identity). Two reasons to prefer it: it names the intent rather than restating the mechanism, and lutaml **raises** if it is given without `collection: true` (`validate_options!`), so a later edit that drops `collection: true` fails loudly instead of silently defaulting a scalar attribute to `[]` — a failure mode a bare `default: -> { [] }` cannot catch. The 10 existing `default: -> { [] }` / `default: []` collection declarations are left alone; this is guidance for new ones, not a migration. **The default does NOT put the key back into the hash, and the mechanism is worth getting right** because the obvious explanation is the wrong one: it is **lutaml's key_value serializer that omits an empty collection**, on its own, whether or not a default is declared — *not* pubid's `canonicalize_hash`. Before the default existed, `default_set?` was `false`, which short-circuits `default_valued?` (`lib/pubid/identifier.rb`) to `false`, so the canonicalizer demonstrably could not have been what dropped the key; the raw lutaml serialization already had no `parts` (verified both ways with `Pubid::Identifier.instance_method(:to_hash).super_method`). The consequence is the useful part: **the serialized shape is byte-identical before and after**, and only what `from_hash` leaves in the attribute changes. So all four checks hold at once: `from_hash(…).parts == []`, `parse(s) == from_hash(parse(s).to_hash)`, and `to_hash` still omits `parts` for the ~81,000 part-less rows of the 88,464-row published index. That last point is why the fix belongs on the **attribute**, not on `to_hash`: emitting `parts: []` would inflate the artifact and be an index-format change forcing a re-crawl. Nothing stored changes, so **no index migration follows**. **The spec lesson generalises past 3GPP**: `serialization_spec.rb` already round-tripped all 11 refs and never caught this, because it compared `to_s` and `to_hash` — both of which were *already correct* (rendering ignores an empty collection, and the hash omits it on both sides). Only `==` sees it. A flavor's round-trip spec must assert `from_hash(id.to_hash) == id`, not just that the two render or serialize alike. **The other flavor with this exact declaration solved it the other way, and is deliberately left alone**: `Pubid::Jis::Identifier#parts` (`lib/pubid/jis/identifier.rb`) is also `collection: true` with no default and shows the identical `[]`/`nil` asymmetry, but JIS hand-writes its `==` (`identifier.rb:96`) and normalises there — `(parts || []) == (other.parts || [])` — so it has no observable defect. Two remedies, then: normalise in `==`, or default the attribute. Prefer the **default**, because it is one line, it fixes every consumer of the attribute rather than only the comparison, and it needs no bespoke `==` to maintain — but the upshot for auditing is that a `collection: true` attribute with no default is only a *suspect*, not a defect: **check `==` before assuming another one is affected.** (hand-off: tgpp-parts-collection-default; consumer follow-up: `relaton/relaton` branch `feat/3gpp-consume-index-v2` can drop its `Bibliography#pubid_match?` workaround — which compares `exclude(*ignore).to_hash`, immune because `to_hash` omits `[]` and `nil` alike — for a plain `pubid.matches?(row_id, ignore:)`.)
- **Parse-failure error class — `Parslet::ParseFailed`, not a bare `RuntimeError`**: `raise "Failed to parse …"` raises a **`RuntimeError`**, and downstream consumers rescue an unparseable reference **by class**: relaton-cli rescues `Parslet::ParseFailed` in two places (`command.rb`, `subcommand_collection.rb`) to print `"<code>" is not a recognized standards identifier`, and nothing else on the path rescues (`Relaton::Db#net_retry` catches only `Relaton::RequestError`). So a flavor that re-wraps the parser's error hands the user a raw Ruby backtrace instead of a sentence. **3GPP now lets `Parslet::ParseFailed` propagate** (`lib/pubid/tgpp/identifier.rb`), joining ISO and ETSI (`lib/pubid/etsi/identifiers/base.rb`, the precedent this copies). The `MAX_INPUT_LENGTH` guard and its **`ArgumentError` stay** — that is a different failure (input too long, not unparseable) and it is the CodeQL ReDoS barrier, so it must keep raising *before* `Parser.parse`. **Still outstanding, deliberately not batched**: 27 of the 43 flavors keep the `raise "Failed to parse …"` idiom, and the `un`/`iho`/`omg`/`doi`/`isbn` specs match on `/Failed to parse/`, so converting them is a separate decision with real spec churn. When migrating one, check first that no spec asserts the message. Locked by `spec/pubid/tgpp/parse_error_spec.rb` (modelled on `spec/pubid/etsi/parse_error_spec.rb`); the pre-existing tgpp assertions survive because `Parslet::ParseFailed < StandardError`. (hand-off: tgpp-parse-failed-propagate; consumer follow-up: `relaton/relaton` branch `feat/3gpp-consume-index-v2`, which has one spec marked `pending` on this.)
- **`typed_stage.original_abbr` must not be set on only one construction path (`from_hash(to_hash) == parse`)**: an identifier's `typed_stage` is filled either by the **parse** path (`Builder#locate_typed_stage` → `Jcgm.locate_stage`, which returns the registry entry untouched, `original_abbr` nil) or by the **lutaml attribute default** (`published_typed_stage`, which used to `dup` the entry and set `original_abbr = canonical_abbreviation`). Setting it on one side only made `from_hash(to_hash) != parse` for every JCGM type the grammar tags with a token — Meeting, Corrigendum, Amendment — while Guide/GumGuide escaped because the parser emits no token for them and `Builder#build` falls back to the same default. **This is a silent, high-blast-radius bug**: `to_s`, `to_urn` and `to_hash` were all *correct*, and `#matches?` is `exclude(*ignore) == other.exclude(*ignore)`, so the difference survives the exclusion and a relaton index lookup (parsed reference vs `from_hash`-ed row) just returns nothing, with no error. - **Input-length guard (ReDoS)**: every public `parse` entry point (`Pubid.parse`, `Pubid::{Flavor}.parse`, and the class-level `{Flavor}::Identifier.parse` / `Parser.parse` funnels) rejects strings longer than `Pubid::MAX_INPUT_LENGTH` (1000) with `ArgumentError` **before** they reach the normalization regexes. Keep the plain regexes and, when adding a new flavor, add the same inline length guard to its `parse` entry (inline `.length` comparison, not a helper, so CodeQL recognizes the barrier).
- **Uniform `Identifier.parse` interface**: every registered flavor exposes **both** a module-level `Pubid::{Flavor}.parse(string)` **and** a class-level `Pubid::{Flavor}::Identifier.parse(string)`, each taking one required positional string and returning a `Pubid::{Flavor}::Identifier` (ISO is a compatible superset: `parse(string, format: :auto)`, still one required positional). The base `Pubid::Identifier` defines **no** `parse`, so each flavor must supply its own. - **Partial reference parsing (optional date/version/year)**: every flavor's `parse` must accept a **partial** reference that omits the trailing publication date / version / edition — e.g. `ISO 9001` (no year), `ETSI EN 300 175` (no version/date), `CCTF REC 2` (no `(YYYY)`) — leaving the omitted attribute **`nil`** (never a default). This is what lets relaton look a document up by a bare reference and match a whole collection (all editions/dates/parts) via the matching primitives (`#matches?(other, ignore:)` = `exclude(*ignore) == other.exclude(*ignore)`); a partial ref only works if it *parses* with the omitted component nil so `exclude`/`matches?` treat it as a wildcard. Most flavors already satisfy this (ISO/IEC/NIST/IEEE/ITU/GOST/BSI/CEN/ETSI…); the **reference implementation** is ETSI — `lib/pubid/etsi/{parser,builder,renderer}.rb` — establishing the uniform three-step pattern: (1) **parser** makes the trailing date/version suffix `.maybe`, each `.maybe` guarding its own leading separator so no trailing separator is demanded (mandatory core stays `publisher + number`, mirroring ISO); (2) **builder** returns `nil` for the absent component instead of building an empty/defaulted one (so the canonical no-defaults `to_hash` drops it); (3) **renderer/urn_generator** append the date/version only when present, so a full id renders byte-identically and a partial renders without a stray separator. The invariant is enforced by the registry-driven cross-flavor spec `spec/pubid/partial_ref_spec.rb` (like `prefixes_spec.rb`/`parse_interface_spec.rb`): a `PARTIAL_REFS` table keyed by the registry's lowercased string flavor name (so `"cen"`, `"cen_cenelec"` and `"3gpp"` all appear) maps each flavor to `{ ref:, omits: }`, two meta-tests assert **every** registered flavor has an entry (and no stale entry) — the forcing function for new flavors — and a per-flavor example parses `ref` and asserts each `omits` attribute is `nil`. **`omits` categories:** (a) flavors with a separable trailing component assert it nil — most use `:year` or `:date`, ETSI uses `%i[version date]`, and note **W3C** (`omits: [:date]`, e.g. `W3C NOTE-xml-names`) and **OASIS** (`omits: [:version]`, e.g. `OASIS EDXL`) *do* carry an optional separable date/version despite otherwise reading like whole-identity ids; (b) truly no-date flavors whose natural form is the whole identity (IANA/XSF/IETF/OGC/PLATEAU/adobe/ecma/ccsds/iala…) use `omits: []`, a plain "still parses" guard; (c) **AMCA currently *requires* the trailing `-YY` year**, so no partial form parses yet — it uses `omits: []` with the canonical **full** ref as a parse-only guard, and adding real partial-ref support for it is outstanding laggard work (it is now the only such laggard). When adding a new flavor, keep the trailing date/version optional and add its `partial_ref_spec.rb` entry. **Registry-enumeration prerequisite:** this spec (and `prefixes_spec`/`parse_interface_spec`) only cover a flavor if `Pubid::Registry.flavor_names` includes it, which requires `eager_load_flavors!` to load its module — its constant filter is `/\A[A-Z][a-zA-Z0-9]+\z/` (**the `0-9` matters**: without it the digit-bearing `W3c` module is silently dropped from the registry, from every registry-driven cross-flavor spec, **and** from `Pubid.parse` prefix auto-routing). Two per-flavor gotchas the pattern surfaces: **fail-corpus migration** (a bare form previously listed in `spec/fixtures/{flavor}/…/fail/` must move to `pass/` once it parses — otherwise the "rejects every fail fixture" spec breaks), and **wrapper forms** where the date lives on an inner identifier (adoption/consolidated/amendment) may need the optionality applied there too. A further gotcha discovered across bipm/cie/csa/ashrae: when a flavor stores the year as a **plain scalar** (`:string`/`:integer` attr) instead of a `Components::Date`, the base `#exclude` **now nils that scalar directly** (the `:year` alias is additive — it keeps `:year` in the exclusion set as well as adding `:date`), so a lone-scalar-year flavor no longer needs an override. An `#exclude` override is required **only** when the scalar carries **sibling/derived attributes** the base can't reach — CSA's `year_format`/`year_prefix`/`original_year_4digit`/`french`, CIE's `date_separator` — in which case it must reset the **whole** cluster after `super` (else a bare ref fails to match a dated hit). ASHRAE's override (`lib/pubid/ashrae/identifiers/base.rb`, a lone `year` `:string` with no siblings, nil-ing `year` after `super`) is now redundant-but-harmless like BIPM's. ASHRAE's partial form additionally required two **parser** fixes: making the type keyword optional in the publisher branch, and excluding the literal `ASHRAE` from the standalone-copublisher `letter.repeat` (via `str("ASHRAE").absent?`) so `ASHRAE 15-2019` stops mis-routing as a copublisher. A no-type ASHRAE ref canonicalizes to the default `Standard` type (`ASHRAE 15` → `ASHRAE Standard 15`).

`lib/pubid/components/` holds reusable parts: Code, Date, Edition, Language, Locality, Publisher, Stage, Type, TypedStage.

### Rendering

`lib/pubid/rendering/` provides shared rendering helpers (base, common, context, date, format, language, numbering, publisher, stage, supplement).

## Testing Notes

- RSpec with `--format documentation`
- Full test suite: `bundle exec rake test:all`
- Integration tests in `spec/integration/` verify cross-gem compatibility
- Per-flavor tests in `spec/pubid/{flavor}/`
- Fixture files in `spec/fixtures/` — one identifier per line in `pass/` and `fail/` directories
- **Fixture files are generated, and the lines are not all plain identifiers.** `spec/fixtures/classify_fixtures.rb` (driven by `bundle exec rake "validation:classify[<flavor>]"`) reads **only** `identifiers/full/*.txt`, then **`rm -rf`s `pass/` and `fail/`** and rebuilds them from the live parser. It writes three line shapes: a plain identifier (byte-exact round-trip), `!input!rendered` in `pass/` (a *normalizing* parse — it succeeds, but `to_s` differs from the input), and `#input# ErrorClass: "message"` in `fail/`. Two consequences. **(1)** A fixture spec that does not split the markers feeds `!input!rendered` to the parser verbatim and counts a spurious failure; `FixtureFileHelper#read_pass_fixture_entries` / `#read_fail_fixture_inputs` (`spec/support/fixture_file_helper.rb`) do the splitting, and their regexes deliberately mirror the writer's so the two cannot drift. Note `read_fixture_file` drops every `#`-leading line, so it returns `[]` for a `fail/` file. **(2)** Anything hand-added to `pass/` but absent from `full/identifiers.txt` is **deleted** by the next classification run — CSA nearly lost the three partial-reference fixtures from PR #134 this way. Add a new fixture to `full/identifiers.txt` and regenerate; **never hand-edit `pass/` or `fail/`**.
- **A fixture spec whose glob is wrong reports 0 examples, not a failure.** `__dir__` in `spec/pubid/<flavor>/` is **two** levels below `spec/fixtures/`, and the flavor directory is **lowercase**. The historical `../../../fixtures/<FLAVOR>` spelling gets both wrong: the extra `..` points at a non-existent repo-root `fixtures/`, and the uppercase name resolves only on a case-insensitive filesystem (so it would still run 0 examples on Linux CI). ITU and CSA are fixed; **ten flavors still carry it** (amca, api, ashrae, asme, astm, bsi, cen_cenelec, idf, jcgm, oiml). `spec/pubid/csa/fixtures_spec.rb` is the reference shape: a **tripwire** example asserting the globs are non-empty (the only thing that makes this defect loud), zero-failure per-file examples over `pass/` **and** `fail/` instead of a 90% threshold, and a **conservation** example asserting the inputs across `pass/` + `fail/` equal those in `full/identifiers.txt` — which is what catches a half-written classification run or a `pass/`-only fixture. (hand-off: ten-dead-fixture-specs.)
